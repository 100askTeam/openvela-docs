I2C驱动开发

I2C驱动子系统框架​

从硬件的角度看，主控芯片通过I2C控制器去访问I2C设备：

  • I2C控制器负责I2C传输，它并不了解传输的数据含义：它只提供传输能力

  • 我们需要阅读I2C设备手册，才能知道所收发的数据的含义

从应用程序角度看：

  • I2C控制器驱动程序提供了传输能力

  • APP可以直接通过I2C控制器驱动程序来读写I2C设备，这时编写APP的人需要阅读芯片手册

  • APP可以通过I2C设备驱动程序来读写I2C设备，编写设备驱动程序的人需要阅读芯片手册，他编写的驱动程序可以让APP开发人员更轻松地使用I2C设备

在上图中，APP可以通过I2C控制器驱动访问I2C设备1、I2C设备n；也可以通过I2C设备n的驱动程序来访问设备n。

从驱动程序的角度看，I2C控制器驱动程序分为上半部、下半部，上半部把接口固定下来并实现通用的代码；下半部是硬件相关的代码。I2C设备驱动程序也可以分为上半部、下半部。下图的I2C设备以触摸屏ft5x06为例。

I2C控制器驱动上半部​

下半部核心结构体​

分析：nuttx/drivers/i2c/i2c_driver.c

我们从上往下分析更容易：从APP角度看问题可以不执着于底层硬件的操作细节。但是对于I2C控制器驱动的下半部，需要先有个大概认识，这有助于看懂上半部的代码。

从I2C硬件的连线图可知，一个I2C控制器上面可以连接多个I2C设备。那么在进行I2C传输时就必须明确这几点：

  • 访问哪个设备？每个I2C设备都有自己独一的设备地址

  • 是读还是写？I2C传输是半双工的，每次传输要么是写要么是读

  • 传输的数据

  • 传输频率

上述信息使用这2个结构体来描述：

  • i2c_msgs_s：被用来描述一个I2C传输，里面有设备地址、频率、读写flags、buffer、长度

  • i2c_transfer_s：里面有i2c_msgs_s数组，可以用来记录多个“I2C传输”

#define I2C_M_READ 0x0001 /* 读取数据，从从机到主机 */

#define I2C_M_NOSTOP 0x0040 /* 消息不应以STOP结束 */

#define I2C_M_NOSTART 0x0080 /* 消息不应以START开始 */

struct i2c_msg_s

{

uint32_t frequency; /* I2C频率 */

uint16_t addr; /* 从机地址（7位或10位） */

uint16_t flags; /* 参见I2C_M_*定义 */

FAR uint8_t *buffer; /* 要传输的缓冲区 */

ssize_t length; /* 缓冲区的字节长度 */

};

struct i2c_transfer_s

{

FAR struct i2c_msg_s *msgv; /* 传输的I2C消息数组 */

size_t msgc; /\* 数组中的消息数量 \*/

};

上面2个结构体可以用来表示要传输的“消息”，谁实现这些消息的传输呢？使用“i2c_master_s”结构体来表示“I2C控制器的下半部”，也就是硬件操作的代码：

struct i2c_master_s

{

FAR const struct i2c_ops_s \*ops; /\* I2C vtable \*/

};

里面的“struct i2c_ops_s”是核心，它有4个函数指针：传输、复位、设置、关闭，代码如下：

struct i2c_ops_s

{

CODE int (*transfer)(FAR struct i2c_master_s *dev,

FAR struct i2c_msg_s \*msgs, int count);

#ifdef CONFIG_I2C_RESET

CODE int (\*reset)(FAR struct i2c_master_s \*dev);

#endif

CODE int (\*setup)(FAR struct i2c_master_s \*dev);

CODE int (\*shutdown)(FAR struct i2c_master_s \*dev);

};

所以，只要得到“i2c_master_s”结构体，就有了I2C传输能力；就可以用它里面的“ops-&gt;transfer”指针来传输“i2c_transfer_s”，而“i2c_transfer_s”里含有一个或多个“i2c_msg_s”。

上半部源码分析​

每个I2C控制器注册的设备节点为“/dev/i2c0”、“/dev/i2c1”等。

源码为“nuttx\drivers\i2c\i2c_driver.c”，向下提供“i2c_register函数；向上提供“static const struct file_operations g_i2cdrvr_fops”标准接口。

关键代码如下：

APP接口与工具​

openvel有I2C工具：apps/system/i2c/i2c_main.c，可以分析它掌握APP接口。

从上小节可以知道，北向接口（APP使用的接口）为“open/close/ioctl”。核心是ioctl，使用示例如下：

//./a.out /dev/i2c-8 0x68 0x60

int main(int argc, char \*\*argv)

{

int fd,ret;

uint8_t val;

char dev_name\[20\];

unsigned int slave_address,reg_address;

struct i2c_transfer_s work;

snprintf(dev_name, sizeof(dev_name),"%s", argv\[1\]);

fd = open(dev_name, O_RDWR);

if (fd \< 0)

{

printf("open failed: %d\n", fd);

return fd;

}

work.msgc = 2;

work.msgv = (struct i2c_msg_s \*)malloc(work.msgc \* sizeof(struct i2c_msg_s));

if (NULL == work.msgv)

{

printf("Memory alloc error\n");

close(fd);

return -1;

}

sscanf(argv\[2\], "%x", &slave_address);

sscanf(argv\[3\], "%x", &reg_address);

val = reg_address;

(work.msgv\[0\]).frequency=400000;

(work.msgv\[0\]).length = 1;

(work.msgv\[0\]).addr = slave_address;

(work.msgv\[0\]).buffer = &val;

(work.msgv\[0\]).flags = I2C_M_NOSTOP;

(work.msgv\[1\]).frequency=400000;

(work.msgv\[1\]).length = 1;

(work.msgv\[1\]).flags = I2C_M_READ;

(work.msgv\[1\]).addr = slave_address;

(work.msgv\[1\]).buffer = &val;

ret = ioctl(fd, I2CIOC_TRANSFER, &work);

if (ret \< 0)

{

printf("i2c: ioctl(I2CIOC_TRANSFER) failed: %d\n",fd);

free( work.msgv);

close(fd);

return -1;

}

printf("reg:0x%02X val:%02x\n", reg_address, val);

free( work.msgv);

close(fd);

return 0;

}

上述代码的核心是“ret = ioctl(fd, I2CIOC_TRANSFER, &work);”，所以使用步骤为：

① 构造“struct i2c_transfer_s”结构体，里面有一个“struct i2c_msg_s”数组

② 构造一个或多个“struct i2c_msg_s”结构体，每个结构体表示一个I2C传输

③ 调用ioctl

ioctl所用结构体如下：

触摸屏驱动开发实例​

I2C设备驱动程序开发方法​

在开发I2C设备驱动时需要知道：

  • 它连接在哪个I2C控制器下面：要得到对应的“i2c_master_s”结构体：这提供了传输能力

  • 还要阅读芯片手册：知道它的设备地址、操作方法

  • 最后，找到合适的“驱动程序上半部”并实现“先半部”：如果没有上半部，可以自己写一个单独的驱动程序

当有了“i2c_master_s”结构体，就有了数据传输能力，剩下的只是实现“file_operations”结构体的各项成员函数。

分析ft5x05.c对外提供的接口​

ft5x06触摸IC的驱动程序为“nuttx/drivers/input/ft5x06.c”。

使用触摸屏很简单，根据“ft5x06.c”提供的“file_operations”结构体，可以知道：

  • read：读取触摸屏数据

  • ioctl：设置、获得频率

  • poll：超时查询

使用“open/read”即可编写出下面的应用程序：

#include &lt;nuttx/input/touchscreen.h&gt;

int main(int argc, char \*\*argv)

{

int len;

{

fd = open(argv\[1\], O_RDWR);

if (fd == -1)

{

printf("can not open file %s\n", argv\[1\]);

}

/* 3. 写文件或读文件 */

{

{

printf("x = %d, y = %d, pressure = %d\n", buffer.point\[0\].x, buffer.point\[0\].y, buffer.point\[0\].pressure);

}

}

close(fd);

return 0;

}

分析ft5x05.c驱动程序​

框架如下：

第1步：从上往下分析，框图如下：

第2步：从下往上分析。

需要在单板启动文件里调用“ft5x06_register(i2c, config, minor)”：

  • 第1个参数是“i2c_master_s”结构体

  • 第2个参数是中断相关的操作，也可以不使用中断

  • 第3个涉及设备名称，比如“/dev/input0”、“/dev/input1”

使用ft5x06触摸屏芯片时，需要设置复位引脚、可以使用中断引脚。这些“独特的、非通用”的操作在下半部里实现：提供一个“ft5x06_config_s”结构体，代码如下：

struct ft5x06_config_s

{

/* 设备特性参数 */

uint8_t address; /* 7位I2C地址（仅使用第0-6位） */

uint32_t frequency; /* 默认I2C通信频率 */

/* IRQ/GPIO访问回调函数。这些操作均通过回调函数封装，

* 以实现FT5X06驱动与不同开发板、MCU在GPIO中断处理上的差异解耦。

*

* attach - 将FT5x06中断处理函数绑定到GPIO中断

* enable - 启用或禁用GPIO中断

* clear - 确认/清除所有未处理的GPIO中断

* wakeup - 向FT5x06发送WAKE中断，将FT5x06从休眠模式切换到工作模式

* nreset - 控制芯片复位引脚（低电平有效）

*/
