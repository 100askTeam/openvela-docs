### I2C驱动子系统框架

从硬件的角度看，主控芯片通过I2C控制器去访问I2C设备：

- I2C控制器负责I2C传输，它并不了解传输的数据含义：它只提供传输能力

- 我们需要阅读I2C设备手册，才能知道所收发的数据的含义

![](/img/openvela/image73.png)

从应用程序角度看：

- I2C控制器驱动程序提供了传输能力

- APP可以直接通过I2C控制器驱动程序来读写I2C设备，这时编写APP的人需要阅读芯片手册

- APP可以通过I2C设备驱动程序来读写I2C设备，编写设备驱动程序的人需要阅读芯片手册，他编写的驱动程序可以让APP开发人员更轻松地使用I2C设备

![](/img/openvela/image74.png)

在上图中，APP可以通过I2C控制器驱动访问I2C设备1、I2C设备n；也可以通过I2C设备n的驱动程序来访问设备n。

从驱动程序的角度看，I2C控制器驱动程序分为上半部、下半部，上半部把接口固定下来并实现通用的代码；下半部是硬件相关的代码。I2C设备驱动程序也可以分为上半部、下半部。下图的I2C设备以触摸屏ft5x06为例。

![](/img/openvela/image75.png)

### I2C控制器驱动上半部

#### 下半部核心结构体

分析：nuttx/drivers/i2c/i2c_driver.c

我们从上往下分析更容易：从APP角度看问题可以不执着于底层硬件的操作细节。但是对于I2C控制器驱动的下半部，需要先有个大概认识，这有助于看懂上半部的代码。

从I2C硬件的连线图可知，一个I2C控制器上面可以连接多个I2C设备。那么在进行I2C传输时就必须明确这几点：

- 访问哪个设备？每个I2C设备都有自己独一的设备地址

- 是读还是写？I2C传输是半双工的，每次传输要么是写要么是读

- 传输的数据

- 传输频率

上述信息使用这2个结构体来描述：

- i2c_msgs_s：被用来描述一个I2C传输，里面有设备地址、频率、读写flags、buffer、长度

- i2c_transfer_s：里面有i2c_msgs_s数组，可以用来记录多个“I2C传输”

上面2个结构体可以用来表示要传输的“消息”，谁实现这些消息的传输呢？使用“i2c_master_s”结构体来表示“I2C控制器的下半部”，也就是硬件操作的代码：

```
struct i2c_master_s

{

FAR const struct i2c_ops_s \*ops; /\* I2C vtable \*/

};

```
里面的“struct i2c_ops_s”是核心，它有4个函数指针：传输、复位、设置、关闭，代码如下：


#### APP接口与工具

openvel有I2C工具：apps/system/i2c/i2c_main.c，可以分析它掌握APP接口。

从上小节可以知道，北向接口（APP使用的接口）为“open/close/ioctl”。核心是ioctl，使用示例如下：

```
//./a.out /dev/i2c-8 0x68 0x60

int main(int argc, char \*\*argv)

{

int fd,ret;

uint8_t val;

char dev_name\[20\];

unsigned int slave_address,reg_address;

struct i2c_transfer_s work;

snprintf(dev_name, sizeof(dev_name),"%s", argv\[1\]);

fd = open(dev_name, O_RDWR);

if (fd \< 0)

{

printf("open failed: %d\n", fd);

return fd;

}

work.msgc = 2;

work.msgv = (struct i2c_msg_s \*)malloc(work.msgc \* sizeof(struct i2c_msg_s));

if (NULL == work.msgv)

{

printf("Memory alloc error\n");

close(fd);

return -1;

}

sscanf(argv\[2\], "%x", &slave_address);

sscanf(argv\[3\], "%x", &reg_address);

val = reg_address;

(work.msgv\[0\]).frequency=400000;

(work.msgv\[0\]).length = 1;

(work.msgv\[0\]).addr = slave_address;

(work.msgv\[0\]).buffer = &val;

(work.msgv\[0\]).flags = I2C_M_NOSTOP;

(work.msgv\[1\]).frequency=400000;

(work.msgv\[1\]).length = 1;

(work.msgv\[1\]).flags = I2C_M_READ;

(work.msgv\[1\]).addr = slave_address;

(work.msgv\[1\]).buffer = &val;

ret = ioctl(fd, I2CIOC_TRANSFER, &work);

if (ret \< 0)

{

printf("i2c: ioctl(I2CIOC_TRANSFER) failed: %d\n",fd);

free( work.msgv);

close(fd);

return -1;

}

printf("reg:0x%02X val:%02x\n", reg_address, val);

free( work.msgv);

close(fd);

return 0;

}

```
上述代码的核心是“ret = ioctl(fd, I2CIOC_TRANSFER, &work);”，所以使用步骤为：

① 构造“struct i2c_transfer_s”结构体，里面有一个“struct i2c_msg_s”数组

② 构造一个或多个“struct i2c_msg_s”结构体，每个结构体表示一个I2C传输

③ 调用ioctl

### 触摸屏驱动开发实例

#### I2C设备驱动程序开发方法

在开发I2C设备驱动时需要知道：

- 它连接在哪个I2C控制器下面：要得到对应的“i2c_master_s”结构体：这提供了传输能力

- 还要阅读芯片手册：知道它的设备地址、操作方法

- 最后，找到合适的“驱动程序上半部”并实现“先半部”：如果没有上半部，可以自己写一个单独的驱动程序

当有了“i2c_master_s”结构体，就有了数据传输能力，剩下的只是实现“file_operations”结构体的各项成员函数。
