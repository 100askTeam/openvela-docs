### ps命令的使用与内部机制

ps命令的作用是“report a snapshot of the current processes”：报告当前时刻各个进程的快照，即显示当前时刻各个进程的状态。

#### 配置和使用

要想使用ps命令的更多功能，可以如下配置：

\# 不配置 CONFIG_SCHED_CPULOAD_NONE,

\# 不配置 CONFIG_NSH_DISABLE_PSSTACKUSAGE

\# 不配置 CONFIG_FS_PROCFS_EXCLUDE_CPULOAD

\# 不配置 CONFIG_NSH_DISABLE_PSHEAPUSAGE

CONFIG_FS_PROCFS=y

CONFIG_SCHED_CPULOAD_SYSCLK=y

CONFIG_MM_BACKTRACE=8

CONFIG_STACK_COLORATION=y

ps命令的用法为：

ps \[-heap\] \[pid1 pid2 ...\]

可以执行这样的命令：

ps \# 查看所有线程状态

ps -heap \# 查看所有线程状态，包括它们使用堆的信息

ps 12 \# 查看PID=12的进程的状态

ps -heap 12 \# 查看PID=12的进程的状态，包括它堆的信息

### top命令的使用与内部机制

top 命令用于实时监控系统中任务（进程）的资源占用情况（如 CPU 使用率、内存使用等），类似 Linux 中的 top 命令。

#### 配置和使用

要想使用top命令，可以如下配置：

\# 不配置 CONFIG_NSH_DISABLE_TOP

\# 不配置 CONFIG_FS_PROCFS_EXCLUDE_CPULOAD

\# 不配置 CONFIG_SCHED_CPULOAD_NONE

\# 不配置 CONFIG_NSH_DISABLE_PS

CONFIG_FS_PROCFS=y

CONFIG_SCHED_CPULOAD_SYSCLK=y

top命令的用法为：

top \[ -n \&lt;num\&gt; \]\[ -d \&lt;delay\&gt;\] \[ -p \&lt;pidlist\&gt;\] \[-h\]

- “-n \&lt;num\&gt;”：显示进程数量（CPU占用率最高的num个进程/线程）

- “-d \&lt;delay\&gt;”：指定刷新间隔（单位：秒，支持小数），不指定时默认间隔为3秒

- “-p \&lt;pidlist\&gt;”：指定监控的任务，格式为“top -p 12,13”，PID间用逗号隔开

- “-h”：显示帮助信息

- 按“ctrl+c”退出

### openvela堆的内部机制

#### 核心结构体

openvela里，“堆”一开始是一个巨大的“空闲内存块”，应用程序可以使用malloc函数、驱动程序可以使用kmm_malloc函数从里面分配出“指定大小的内存”，使用完毕后再通过free函数、kmm_free函数把它“还回去”。需要说明的是，“kmm_malloc/kmm_free”就是“malloc/free”。

经过多次malloc、free后，堆里会有“多个零散的、未使用的空闲块”、“多个在使用的空闲块”。

openvela的堆算法里，怎么管理这些“未使用的内存块”、“在使用的内存块”？

使用“struct mm_heap_s”结构体来表示“堆”，里面的“struct mm_freenode_s mm_nodelist\[MM_NNODES\]”是多个链表，每个链表里存放“空闲chunk”（空闲内存块）：

![](/img/openvela/image231.png)

空闲内存块、正在使用的内存块，都被称为“chunk”，chunk由头部的node结构体、紧随其后的内存组成，它们的结构如下：

![](/img/openvela/image232.png)

空闲chunk、被分配出去（被占用）的chunk，它们的头部分别使用这2个结构体来表示：struct mm_freenode_s、struct mm_allocnode_s。代码如下：

![](/img/openvela/image233.png)

#### 堆的算法

openvela的堆算法，核心在于：

- 使用不同的链表来管理“各个size级别的、空闲的chunk”  
  比如“struct mm_heap_s”结构体里，使用mm_nodelist\[0\]链表记录“size \&gt;= 2^6, size \&lt; 2^7”的chunk；使用mm_nodelist\[1\]链表记录“size \&gt;= 2^7, size \&lt; 2^8”的chunk。  
  并且，这些链表里各个chunk按照从小到大排序

- 执行malloc(size)时，根据size找到mm_nodelist\[x\]链表，遍历里面的node，找到最合适的chunk，后面将返回它的数据块的地址；如果mm_nodelist\[x\]链表为空，还会进入下一级的mm_nodelist\[x+1\]链表来继续查找

- 如果这个chunk太大，还要把它拆分：拆分出来的chunk再加入某个mm_nodelist\[y\]链表

- 执行free(ptr)时，根据ptr往前确定node结构体，把这个node放回某个mm_nodelist\[z\]链表

- 如果这个chunk前面、后面有相邻的chunk，还要合并起来得到新的chunk：因为大小发生了变化，还要重新放入某个mm_nodelist\[w\]链表

看视频。

函数调用关系：

\# 内核/驱动调用 kmm_malloc 也是调用 malloc

malloc

```
ret = mm_malloc(USR_HEAP, size);

// 难点

alignsize = MM_ALIGN_UP(size + MM_ALLOCNODE_OVERHEAD);

ndx = mm_size2ndx(alignsize);

// 遍历heap-\>mm_nodelist\[ndx\]

// 找到第1个适合的freenode

// 1. 如果大小差不多

// 把这个freenode从链表中移除

// 2. 如果太大了(拆分出来的空间还大于node头部)

// 拆分出新node

// 把新node放入链表

// 返回node之后的内存

ret = (FAR void \*)((FAR char \*)node + MM_SIZEOF_ALLOCNODE);

// 记录调试信息，比如pid, 序列号seq, backtrace

MM_ADD_BACKTRACE(heap, node);

```
结果如下：

- malloc(size)时，根据size计算链表ndx

- 遍历g_mmheap-\&gt;mmnodelist\[ndx\]，找到合适的freenode

- 如果这个freenode太大，还要把它拆分：拆分出来的freenode再加入某个mm_nodelist\[y\]链表

- 返回“freenode+头部”，就是返回头部后面的buffer给调用者

malloc函数里比较难以理解的是：它会占用下一个node的“preceding”。下一个node的preceding表示物理上相邻的、上一个空闲的chunk的大小。但是当前node已经被占用了，“下一个node的preceding”就没有意义了，那就把它用起来。

### “ctrl+?”命令的使用与内部机制

注意：“Ctrl+?”里的问号，可以表示很多字符。Ctrl加上不同的字符代表一些特殊字符。通过串口发送一些特殊字符给开发板，可以触发一些事情。

可见 ASCII 字符的编码范围是 0x20（十进制 32）到 0x7E（十进制 126），共 95 个字符。对于编码值小于0x20的特殊字符，可以使用Ctrl和字母产生，规则是：可见字符（大写）的ASCII码是m，Ctrl+这个可见字符的编码就是“m-64”。

比如“C”的ASCII码是0x43，那么Ctrl+C的编码就是0x03。

### 其他命令

几个常用命令用法如下：

nsh\&gt; help mb

mb usage: mb \&lt;hex-address\&gt;\[=\&lt;hex-value\&gt;\] \[\&lt;hex-byte-count\&gt;\]

nsh\&gt; help mh

mh usage: mh \&lt;hex-address\&gt;\[=\&lt;hex-value\&gt;\] \[\&lt;hex-byte-count\&gt;\]

nsh\&gt; help mw

mw usage: mw \&lt;hex-address\&gt;\[=\&lt;hex-value\&gt;\] \[\&lt;hex-byte-count\&gt;\]

nsh\&gt; help hexdump

hexdump usage: hexdump \&lt;file or device\&gt; \[skip=\&lt;bytes\&gt;\] \[count=\&lt;bytes\&gt;\]

nsh\&gt; help pidof

pidof usage: pidof \&lt;name\&gt;

“mb/mh/mw”命令，分别用来以“字节/半字(2字节)/字(4字节)”为单位读取或写如某个地址。

示例如下：

nsh\&gt; mb 40000000 \# 读0x40000000地址数据，读1个字节

0x40000000 = 0x67 \# 值为0x67

nsh\&gt; mb 40000000=77 \# 写0x40000000地址，写1个字节，数值为0x77

0x40000000 = 0x67 -\&gt; 0x77

nsh\&gt; mb 40000000 \# 读出验证

0x40000000 = 0x77

nsh\&gt; mb 40000000 2 \# 从0x40000000开始读2个字节

0x40000000 = 0x77

0x40000001 = 0x45

“hexdump”明白可以用来读取文件或驱动程序，“skip=N”表示跳过前面N字节，“count=M”表示读取M字节。比如：

nsh\&gt; hexdump /data/1.wav count=10

/data/1.wav at 00000000:

0000: 52 49 46 46 c6 29 00 00 57 41 RIFF.)..WA
