### openvela中断体系

#### ARMv7中断体系与处理流程

GIC：通用中断控制器（“Generic Interrupt Controller”）。GIC 是 ARM 公司开发的一个中断硬件 IP，主要用于管理外设中断，是联系外设中断和 CPU 的桥梁，也是各 CPU 之间中断互联的通道。它可以做到使能或禁止中断、把中断分组、在多核系统中将中断分配到不同处理器上、设置电平触发还是边沿触发方式等。

假设按键引脚被配置为中断功能，按键被按下或松开时，GPIO模块检测到信号发生变化后向GIC发出中断，GIC再向CPU发出中断。

![](/img/openvela/image124.png)

CPU每执行完一条指令都会检查有无中断/异常产生，发现有中断/异常产生后，就会暂停当前的程序去处理中断/异常。

对于ARMv7架构，有如下异常向量表：

![](/img/openvela/image125.png)

A7的向量表中，放置的是各类异常的“跳转指令”。

比如发生“Reset”异常时，CPU就会从向量表里找到第0项，执行“ldr pc, .Lresethandler”指令。

比如发生任何的中断时，CPU就会从向量表里找到第6项，执行“ldr pc, .Lirqhandler”指令去处理中断。

- 跳转之前，硬件只会保存CPSR寄存器

- 跳转之后，软件要保存现场

- 处理中断的函数执行完毕，返回之前，软件恢复现场、恢复CPSR寄存器

怎么处理中断呢？

在CPU的角度，它可以从GIC里读取到“发生了n号”中断，但是它无法知道中断起源是“GPIO的m号引脚”。所以，我们需要给“n号GIC中断”提供处理函数A。函数A要去读取GPIO控制器，分辨出是“m号引脚触发了中断”，然后调用它的处理函数B。

在上述场景里，我们需要提供两个中断处理函数：n号GIC中断处理函数A，m号GPIO引脚的中断处理函数B。

假设I2C0模块直接向GIC控制器发出“k号”中断，GIC的k号中断来源只有I2C0模块，那么可以给“k号GIC中断”只提供一个处理函数C。
