语音功能开发

音频开发基础概念​

硬件参数​

录制和播放声音的本质是将耳朵听到的声音进行采样、保存和恢复。在采集声音时，采集频率越高、采样精度（每个数据用多少bit来表示）越高，播放时的效果就越逼真。

在图中，如果采集声音时t1至t6的间隔越短，那么恢复的波形就越逼真。记录v1至v6时，使用的比特数越多，得到的数值精度越高，右侧恢复的波形也会更加逼真。

如果能将左耳和右耳听到的声音分别采样并记录下来，在播放时通过两个喇叭或耳机播放出来，就能听到立体声效果。在原始音频数据里，左右声道的数据交叉存放，比如“v1,v2,...”是左声道采样的数据，“v1’v2’,...”是右声道采样的数据，在原始文件中存放如下：

v1v1’v2v2’,...

这就涉及了声音采集和播放的三个关键参数：采样频率、采样精度和声道数。

软件参数​

编写软件时，也涉及采样频率、采样精度和声道数。其中采样精度使用format来表示，有如下这些格式，这些格式不仅表示了采样精度，还表示了数据的保存格式（大字节序、小字节序）：

……

SND_PCM_FORMAT_S16_LE

SND_PCM_FORMAT_S16_BE

SND_PCM_FORMAT_S24_LE

SND_PCM_FORMAT_S24_BE

……

还有其他概念，如下。

① 帧（frame）：一帧表示一个采样点，对于单声道一帧有一个数据，对于双声道一帧有两个数据。

② period：每次读写声音数据的最小单位是多少，它的单位是帧。如果period设置得很小，那么录制或播放一段声音时需要频繁发起read/write操作，效率很低。如果period设置得很大，如果采集的声音要转发出去，那么对方就会感觉声音很卡顿；如果播放的声音来自网络，程序就要收集很多的数据才能播放，也会感觉到卡顿。

③ buffer_size：音频缓冲区大小，单位也是帧，对录音和播放很关键。假设APP读取数据后进行处理，处理的时间多长了，这可能会导致数据丢失。这时可以把buffer设置得比较大，在恶劣情况下可以缓存更多数据。

在阅读openvela里aplay、arecord的代码时，会看到如下函数，它就是用来设置这5个参数的：

int set_param(snd_pcm_t \*handle, snd_pcm_format_t format,

unsigned int rate, unsigned int channels,

snd_pcm_uframes_t period_size,

snd_pcm_uframes_t buffer_size);
